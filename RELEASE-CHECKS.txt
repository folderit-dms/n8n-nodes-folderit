Folderit n8n 0.3.0 - published, 2026-10-10

Verified locally
- TypeScript build, official n8n lint and 43 contract tests.
- Native n8n 2.42.5 with Node 24.21.0: document upload/download, OAuth token
  renewal, search, integer metadata update/read/clear, version upload/history,
  manual workflow start/status and scheduled version-event polling.
- Editor: credential, account, folder, metadata field, select-option and workflow
  selectors; binary download/text extraction and exact-version trigger preview.
- Exact binary comparisons, checkpoint persistence after emitted events, and
  quiet-poll persistence across restart with durable polling (README settings).
  Quiet test produced zero executions; all scheduled QA workflows are inactive.
- Missing startup checkpoint fails before API requests instead of rebaselining.
- No external runtime dependencies or embedded credentials in the npm archive.

Dependency assessment
- npm audit reports 23 upstream tooling/peer-tree advisories: 5 moderate,
  17 high and 1 critical. This is not a vulnerability-free dependency tree.
- The critical GHSA-8r5x-fm3f-whwj affects Handlebars compilation of untrusted
  AST objects. Official advisory says template-string-only use is unaffected:
  https://github.com/advisories/GHSA-8r5x-fm3f-whwj
- Inspected @n8n/node-cli 0.51.3 template/core.js and commands/release.js:
  both compile UTF-8 template strings read from files, not AST objects.
  Our build/lint/test/pack workflow does not invoke CLI scaffolding or release.
  Based on these call sites, the critical exploit path is not reached here.
- The CLI still pins Handlebars 4.7.9, including upstream CLI 0.51.4.
  Await a compatible upstream fix; official n8n lint prohibits overrides.
- No third-party runtime dependencies are bundled by this connector.
  n8n-workflow is supplied by the host; host advisories remain the operator's
  responsibility. Other tooling advisories are not claimed patched.
- Build dependencies run without publishing credentials in a separate job.
  The release job only stages the tested archive using OIDC and provenance;
  a maintainer must approve the staged release through npm with 2FA.
